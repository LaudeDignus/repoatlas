    RÉSULTATS DE L’EXPLORATION

    Voir le dépôt ↗

    Ajouts d’abord · Retard croissant

    Comment lire ces résultats ?

    RepoAtlas lit au maximum 20 forks récents, 10 forks étoilés et 30 pull requests ouvertes. Il sélectionne jusqu’à 16 branches, dont au plus 10 branches de PR. Cette exploration est un échantillon, pas un inventaire exhaustif.

    Les ajouts sont repérés à partir des titres et descriptions des PR, messages de commits et noms de fichiers. Les catégories sont attribuées par mots-clés ; aucune IA n’est appelée et aucun correctif n’est exécuté ou certifié. Une PR ouverte peut nécessiter des adaptations.

    « En avance » désigne les commits présents sur la branche comparée mais absents de la référence. « En retard » désigne les commits de la référence qui manquent à cette branche. Les fichiers affichés correspondent à la différence depuis l’ancêtre commun, comme dans la comparaison GitHub.

    Les réponses GitHub restent en mémoire pendant dix minutes pour économiser le quota. Un redémarrage efface ce cache. Votre jeton éventuel reste dans le serveur local.

    VOTRE ACCÈS, EN LOCAL

    Configurer GitHub

    Un jeton personnel augmente le quota de lecture. Il reste dans votre serveur local.

    1. Créer un jeton à permissions fines sur GitHub ↗

      Choisissez votre compte, une expiration et l’accès aux dépôts publics en lecture. Aucune permission d’écriture n’est nécessaire.

    2. Dans le terminal du projet, lancez :
      npm run github:token

      Collez le jeton dans la saisie masquée, puis appuyez sur Entrée. La commande le vérifie auprès de GitHub et l’enregistre dans .env, avec un accès réservé à votre utilisateur.

    3. Revenez dans RepoAtlas et rechargez la page. Le jeton est pris en compte sans redémarrer le serveur ; l’en-tête indique alors « GitHub · Jeton configuré ».

    Ne publiez pas votre jeton. Le fichier .env est déjà exclu de Git. Les quotas GitHub restent applicables avec un jeton.
